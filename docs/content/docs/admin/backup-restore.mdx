ربات می‌تواند به‌صورت خودکار یا دستی از **دیتابیس** و فایل **`.env`** بکاپ بگیرد و فایل ZIP را در کانال بکاپ شما بفرستد. با همین فایل می‌توانید ربات را روی یک سرور جدید دقیقاً به همان حالت قبلی برگردانید.

<Callout type="info" title="خلاصهٔ ریستور در یک نگاه">
نصب ربات روی سرور جدید (با همان توکن) ← ورود به phpMyAdmin با یوزر `root` ← Drop کردن همهٔ جدول‌های `pasarguardbot` ← Import فایل `database.sql` ← اجرای `pasarguardbot update` ← بررسی لاگ با `pasarguardbot logs`
</Callout>

---

## گرفتن بکاپ

### پیش‌نیاز: کانال بکاپ

ابتدا از **پنل مدیریت → 📝 مدیریت لاگ‌ها** کانال **🗄 بکاپ ربات** را ست کنید ([مدیریت لاگ‌ها](/docs/admin/logs)). بدون این کانال بکاپ ارسال نمی‌شود و پیام «❌ کانال لاگ بکاپ تنظیم نشده است» را می‌بینید.

<Callout type="warn" title="کانال بکاپ باید خصوصی باشد">
داخل فایل بکاپ، `.env` شما هست که شامل **توکن ربات** و **رمزهای دیتابیس** است. کانال بکاپ را حتماً خصوصی نگه دارید و کسی را عضو نکنید.
</Callout>

### منوی بکاپ

از **پنل مدیریت → 📦 بکاپ ربات**:

| دکمه | کار |
|------|-----|
| `🚀 بکاپ همین الان` | همان لحظه بکاپ می‌گیرد و به کانال بکاپ می‌فرستد |
| `⚙️ تنظیم فاصله (⏱ فاصله: هر N ساعت)` | فاصلهٔ بکاپ خودکار را به **ساعت** بفرستید (فقط عدد، مثلاً `24`). عدد `0` بکاپ خودکار را خاموش می‌کند (`⏸ خودکار خاموش`) |
| `🔙 بازگشت به پنل` | بازگشت |

- مقدار پیش‌فرض بکاپ خودکار **هر ۲۴ ساعت** است و بعد از تغییر بلافاصله زمان‌بندی می‌شود.
- از **پنل تحت وب ← ابزارها ← بکاپ دیتابیس** هم می‌توانید بکاپ را به چت خودتان یا کانال لاگ بفرستید.
- بکاپ فقط برای دیتابیس **MariaDB/MySQL** پشتیبانی می‌شود (نصب پیش‌فرض همین است).

### داخل فایل بکاپ چیست؟

نام فایل شبیه `pasarguardbot-backup-YYYYMMDD-HHMMSS.zip` است و داخلش:

<Files>
  <Folder name="pasarguardbot-backup-20261009-120000.zip" defaultOpen>
    <File name="database.sql — دامپ کامل دیتابیس (همهٔ کاربران، سرویس‌ها، پنل‌ها، تنظیمات، متن‌ها و…)" />
    <File name=".env — تنظیمات نصب قبلی (توکن، رمزهای دیتابیس و…)" />
  </Folder>
</Files>

**داخل بکاپ نیست:** سشن تلگرام، داده‌های Redis، آیکون‌های آپلودی وب‌اپ (`data/pwa_icons`)، گواهی‌های SSL و خود پنل پاسارگارد.

<Callout type="info" title="کلیدها داخل دیتابیس هستند">
در نسخه‌های جدید، `crypto_key` (رمزنگاری پسورد پنل‌ها و نمایندگی‌ها) و `webhook_secret` (هدر وب‌هوک پنل) داخل جدول **`secrets`** دیتابیس ذخیره می‌شوند؛ پس با ایمپورت `database.sql` خودکار برمی‌گردند و وب‌هوک پنل‌ها هم بدون تغییر کار می‌کند.
</Callout>

## ریستور بکاپ — قدم‌به‌قدم

<Steps>
<Step>

### نصب ربات روی سرور جدید

ربات را طبق [راهنمای نصب](/docs/getting-started/install) روی سرور جدید نصب کنید و **همان `BOT_TOKEN` و `ADMIN_ID` قبلی** را وارد کنید. ربات با آخرین نسخه نصب می‌شود.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/AmirKenzo/PasarguardBot/main/scripts/pasarguardbot.sh)
```

</Step>
<Step>

### برداشتن یوزر و پسورد دیتابیس

فایل `.env` سرور **جدید** را باز کنید:

```bash
pasarguardbot edit-env
```

مقدار این متغیر را یک جا کپی کنید (بعد بدون ذخیره تغییر، از ویرایشگر خارج شوید):

```text
MARIADB_ROOT_PASSWORD=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

اگر ویرایشگر پرسید `Restart the bot? (Y/n)`، چون چیزی عوض نکرده‌اید می‌توانید `n` بزنید.

</Step>
<Step>

### ورود به phpMyAdmin

در مرورگر باز کنید (به‌جای IP، آیپی سرور خودتان یا دامنه را بگذارید):

```text
http://IP_SERVER:6163
```

- **Username:** `root`
- **Password:** مقدار `MARIADB_ROOT_PASSWORD` که کپی کردید

<ZoomImage src="/images/backup-restore/01-login.webp" alt="ورود به phpMyAdmin با یوزر root" />

</Step>
<Step>

### پاک کردن همهٔ جدول‌های فعلی (Drop)

نصب تازه جدول‌های خالی ساخته؛ باید قبل از ایمپورت کاملاً پاک شوند:

1. از ستون سمت چپ دیتابیس **`pasarguardbot`** را انتخاب کنید.
2. پایین لیست جدول‌ها تیک **Check all** را بزنید تا همهٔ جدول‌ها انتخاب شوند.
3. از لیست کشویی **With selected:** گزینهٔ **Drop** را انتخاب کنید.

<ZoomImage src="/images/backup-restore/02-drop-select.webp" alt="انتخاب همهٔ جدول‌ها و Drop" />

4. صفحهٔ تأیید باز می‌شود؛ **Yes** را بزنید. بعد از این مرحله هیچ جدولی نباید در دیتابیس باقی بماند.

<ZoomImage src="/images/backup-restore/03-drop-confirm.webp" alt="تأیید Drop همهٔ جدول‌ها" />

</Step>
<Step>

### ایمپورت فایل `database.sql`

1. فایل ZIP بکاپ را از کانال دانلود و Extract کنید تا به `database.sql` برسید.
2. در phpMyAdmin (دیتابیس `pasarguardbot` انتخاب باشد) تب **Import** را باز کنید.
3. روی **Choose File** بزنید و فایل `database.sql` را انتخاب کنید.
4. بقیهٔ تنظیمات را دست نزنید و پایین صفحه **Import** را بزنید.

<ZoomImage src="/images/backup-restore/05-import.webp" alt="تب Import و انتخاب فایل database.sql" />

بعد از چند ثانیه (برای بکاپ‌های بزرگ چند دقیقه) پیام سبز موفقیت را می‌بینید:

<ZoomImage src="/images/backup-restore/07-import-success.webp" alt="پیام موفقیت Import" />

<Callout type="info" title="فایل خیلی بزرگ است؟">
phpMyAdmin در نصب Docker تا **256 مگابایت** فایل قبول می‌کند. اگر بکاپ بزرگ‌تر بود، فایل را روی سرور آپلود کنید و از ترمینال ایمپورت کنید:

```bash
cd /opt/pasarguardbot && source .env
docker exec -i pasarguardbot-mariadb mariadb -uroot -p"$MARIADB_ROOT_PASSWORD" < /root/database.sql
```
</Callout>

</Step>
<Step>

### بررسی اطلاعات ریستورشده

دوباره روی دیتابیس `pasarguardbot` بزنید. باید جدول‌های ربات شما با اطلاعات قبلی برگشته باشند؛ مثلاً ستون **Rows** جدول **`user`** را با تعداد کاربران ربات قبلی‌تان مقایسه کنید.

<ZoomImage src="/images/backup-restore/08-verify.webp" alt="بررسی تعداد کاربران و جدول secrets" />

روی جدول **`secrets`** هم بزنید؛ باید دو ردیف `crypto_key` و `webhook_secret` داشته باشد:

<ZoomImage src="/images/backup-restore/09-secrets.webp" alt="ردیف‌های جدول secrets" />

اگر جدول `secrets` وجود نداشت یا خالی بود، حتماً بخش [ربات‌های قدیمی (نسخه 2.1.4 و پایین‌تر)](#old-versions) را انجام دهید.

</Step>
<Step>

### آپدیت و مایگریشن خودکار

بعد از ایمپورت **حتماً** این دستور را بزنید:

```bash
pasarguardbot update
```

اگر بکاپ از نسخهٔ قدیمی‌تر ربات باشد، ساختار دیتابیس خودکار به آخرین نسخه **مایگریت** می‌شود و ربات با دیتابیس ریستورشده و کلیدهای درست از نو بالا می‌آید. اگر این مرحله را انجام ندهید با ارور و مشکل روبه‌رو می‌شوید.

</Step>
<Step>

### بررسی لاگ ربات

```bash
pasarguardbot logs
```

مطمئن شوید ربات بدون ارور اجرا شده است (برای خروج `Ctrl+C`). بعد در تلگرام:

- `/start` و `/panel` را بزنید و ببینید پنل مدیریت باز می‌شود.
- از **📚 منوی پنل‌ها** اتصال پنل‌ها را چک کنید.
- اگر نمایندگی دارید، **نمایش رمز ورود** یکی از نمایندگی‌ها را تست کنید.
- اگر IP یا دامنهٔ سرور عوض شده، آدرس وب‌هوک را در پنل پاسارگارد به آدرس جدید تغییر دهید (هدر `x-webhook-secret` همان قبلی است) — [اطلاع‌رسانی حجم و زمان](/docs/admin/panels/notifications).

</Step>
</Steps>

## ربات‌های قدیمی (نسخه 2.1.4 و پایین‌تر) [#old-versions]

<Callout type="error" title="خیلی مهم برای بکاپ‌های قدیمی">
در نسخه‌های **2.1.4 و پایین‌تر**، کلیدهای `CRYPTO_KEY` و `WEBHOOK_SECRET` داخل فایل `.env` بودند، نه دیتابیس. اگر این مرحله را انجام ندهید **پنل‌ها به ربات وصل نمی‌شوند** و **نمایندگی‌ها کار نمی‌کنند**.
</Callout>

**چطور بفهمم بکاپم قدیمی است؟** داخل فایل `database.sql` بکاپ کلمهٔ `secrets` را جستجو کنید. اگر چیزی پیدا نشد — یا بعد از ریستور در phpMyAdmin جدول `secrets` نبود/خالی بود — بکاپ شما قدیمی است.

**راه‌حل:**

1. فایل `.env` **داخل ZIP بکاپ** را باز کنید و مقدار `CRYPTO_KEY` و `WEBHOOK_SECRET` را پیدا کنید.
2. روی سرور جدید `.env` را باز کنید:

   ```bash
   pasarguardbot edit-env
   ```

3. این دو خط را به انتهای فایل اضافه کنید و به‌جای `KENZO` مقدار **دقیق** همان دو متغیر از `.env` بکاپ خودتان را بگذارید:

   ```text
   WEBHOOK_SECRET=KENZO
   CRYPTO_KEY=KENZO
   ```

4. ذخیره کنید و بعد دستور آپدیت را بزنید تا مایگریشن، کلیدها را از `.env` به جدول `secrets` منتقل کند:

   ```bash
   pasarguardbot update
   ```

5. با `pasarguardbot logs` مطمئن شوید ربات بدون خطا بالا آمده است.

<Callout type="info">
اگر نسخهٔ ربات قبلی شما بالاتر از 2.1.4 بوده، **هیچ تغییری** در `.env` لازم نیست؛ همه‌چیز داخل `database.sql` است.
</Callout>

---

## چک‌لیست سریع ریستور

1. نصب تازهٔ ربات روی سرور جدید با همان توکن
2. `pasarguardbot edit-env` و کپی `MARIADB_ROOT_PASSWORD`
3. ورود به `http://IP:6163` با یوزر `root`
4. دیتابیس `pasarguardbot` ← Check all ← With selected: Drop ← Yes
5. تب Import ← انتخاب `database.sql` ← Import
6. بررسی تعداد کاربران و جدول `secrets`
7. (فقط بکاپ قدیمی) اضافه کردن `CRYPTO_KEY` و `WEBHOOK_SECRET` به `.env`
8. `pasarguardbot update`
9. `pasarguardbot logs` و تست ربات

## اشتباهات رایج

| اشتباه | نتیجه |
|--------|--------|
| ایمپورت بدون Drop کردن جدول‌های نصب تازه | خطای تداخل جدول یا ایمپورت ناقص |
| فراموش کردن `pasarguardbot update` بعد از ایمپورت | دیتابیس مایگریت نمی‌شود و ربات ارور می‌دهد |
| بکاپ قدیمی (≤ 2.1.4) بدون اضافه کردن `CRYPTO_KEY` و `WEBHOOK_SECRET` | پنل‌ها وصل نمی‌شوند، نمایندگی‌ها کار نمی‌کنند |
| جایگزین کردن **کل** `.env` قدیمی روی سرور جدید | رمز دیتابیس و آدرس‌ها با نصب جدید نمی‌خواند و ربات بالا نمی‌آید |
| عمومی بودن کانال بکاپ | لو رفتن توکن ربات و رمزهای دیتابیس |
| ایمپورت قبل از نصب ربات | phpMyAdmin و دیتابیس هنوز وجود ندارند |
