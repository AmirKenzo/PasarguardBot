قبل از هر چیز، لاگ ربات را ببینید. بیشتر مشکلات همان‌جا توضیح داده شده‌اند:

```bash
pasarguardbot logs
```

(لاگ زندهٔ همهٔ سرویس‌ها؛ با `Ctrl+C` خارج شوید.)

## نصب و سرور [#server]

<Accordions>
<Accordion title="ربات بعد از نصب جواب /start را نمی‌دهد">

1. **صبر کنید.** در اولین اجرا MariaDB دیتابیس را می‌سازد و ربات تا سالم شدن دیتابیس منتظر می‌ماند. این کار ممکن است **چند دقیقه** طول بکشد.
2. لاگ را ببینید: `pasarguardbot logs`. باید پیام اجرای مایگریشن (`Running database migrations...`) و بعد بالا آمدن ربات را ببینید.
3. وضعیت کانتینرها: `pasarguardbot status`. هر چهار کانتینر باید `running` باشند.
4. `BOT_TOKEN` را در `.env` چک کنید (`pasarguardbot edit-env`).
5. اگر کانتینرها به اینترنت وصل نمی‌شوند (خطای اتصال به تلگرام یا timeout)، بخش «مشکل شبکهٔ Docker» را پایین‌تر ببینید.
6. اگر ربات برای شما جواب می‌دهد ولی برای کاربران نه، احتمالاً **وضعیت ربات** خاموش است (پایین‌تر).

</Accordion>
<Accordion title="BOT_TOKEN را عوض کردم ولی هنوز ربات قبلی جواب می‌دهد">

سشن تلگرام ربات قبلی در پوشهٔ `sessions` ذخیره شده و با آن دوباره وصل می‌شود. ربات را متوقف کنید، فایل سشن را پاک کنید و دوباره راه بیندازید:

```bash
cd /opt/pasarguardbot
docker compose stop bot
rm -f sessions/KenzoSession.session
pasarguardbot restart
```

</Accordion>
<Accordion title="هنگام نصب می‌گوید پورت اشغال است">

```text
[!] Port 6160 appears to be in use.
```

برنامه‌ای که پورت را گرفته پیدا کنید:

```bash
ss -ltnp | grep -E ':(6160|6161|6162|6163)\s'
```

آن را متوقف کنید یا پورت ربات را با `FASTAPI_PORT` عوض کنید. جزئیات: [پورت‌ها](/docs/getting-started/ports#busy).

</Accordion>
<Accordion title="دانلود ایمیج Docker خطا می‌دهد (docker compose pull failed)">

- ایمیج ربات فقط برای معماری‌های **`amd64`** و **`arm64`** ساخته می‌شود. معماری سرور را با `uname -m` چک کنید (`x86_64` = amd64، `aarch64` = arm64). روی معماری‌های دیگر (مثل armv7) نصب ممکن نیست.
- دسترسی سرور به `ghcr.io` و Docker Hub را چک کنید. بعضی دیتاسنترها این دامنه‌ها را محدود می‌کنند.
- اگر شبکهٔ کانتینرها مشکل دارد، بخش بعدی را ببینید.

</Accordion>
<Accordion title="مشکل شبکهٔ Docker (کانتینرها به اینترنت یا به هم وصل نمی‌شوند)">

روی بعضی سرورهای Ubuntu یک فایل Netplan شبکهٔ bridge داکر را خراب می‌کند. از منو گزینهٔ **`11) Fix Docker network`** را بزنید:

1. اول **`1) Check Docker Bridge`** تا مشکل تأیید شود.
2. اگر تست شکست خورد، **`2) Repair Docker Bridge`**.
3. اگر بعد از تعمیر مشکلی پیش آمد، **`3) Rollback Netplan Repair`**.

ممکن است یک ریبوت لازم شود. جزئیات: [منوی مدیریت → Fix Docker network](/docs/getting-started/cli-menu#docker-network).

</Accordion>
<Accordion title="یوزر و رمز phpMyAdmin را فراموش کرده‌ام">

همه در فایل `/opt/pasarguardbot/.env` هستند:

```bash
grep MARIADB_ /opt/pasarguardbot/.env
```

- یوزر: مقدار `MARIADB_USER` (معمولاً `pasarguardbot`) با رمز `MARIADB_PASSWORD`
- یا یوزر `root` با رمز `MARIADB_ROOT_PASSWORD`

آدرس phpMyAdmin: `http://SERVER_IP:6163` (یا `pasarguardbot urls`).

</Accordion>
<Accordion title="فایل‌های لاگ کجا هستند؟">

- لاگ فایلی ربات: `/opt/pasarguardbot/logs/app.log` و خطاها در `/opt/pasarguardbot/logs/error.log`
- لاگ کانتینرها: `pasarguardbot logs` (زنده) یا منو گزینهٔ **`4) View logs`**

سطح جزئیات با `LOG_LEVEL` در `.env` تنظیم می‌شود. [پیکربندی](/docs/getting-started/configuration#file-logging)

</Accordion>
</Accordions>

## مدیریت و آپدیت [#manage]

<Accordions>
<Accordion title="چطور ربات را آپدیت کنم؟">

```bash
pasarguardbot update
```

برنچ را بپرسد، Enter بزنید (`main`). اسکریپت خودش را به‌روز می‌کند، ایمیج جدید را می‌گیرد، کانتینرها را از نو می‌سازد و مایگریشن دیتابیس را خودکار اجرا می‌کند. `.env` و دیتا حفظ می‌شوند. [جزئیات](/docs/getting-started/cli-menu#update)

</Accordion>
<Accordion title="چطور بین برنچ main و dev جابه‌جا شوم؟">

همان `pasarguardbot update` را بزنید و در سؤال برنچ، `1` (main) یا `2` (dev) را انتخاب کنید. تگ ایمیج خودکار عوض می‌شود (`latest` یا `dev`).

`dev` برای تست است و ممکن است ناپایدار باشد. قبل از جابه‌جایی حتماً از **📦 بکاپ ربات** بکاپ بگیرید.

</Accordion>
<Accordion title="چطور ادمین دیگری اضافه کنم؟">

آیدی عددی تلگرام ادمین جدید را با کاما به `ADMIN_ID` اضافه کنید:

```bash
pasarguardbot edit-env
# ADMIN_ID=111111111,222222222
```

ذخیره کنید و به `Restart the bot? (Y/n):` با Enter جواب دهید. همهٔ آیدی‌های این لیست دسترسی کامل پنل مدیریت را دارند.

</Accordion>
<Accordion title="چطور بکاپ را روی سرور جدید ریستور کنم؟">

ربات را روی سرور جدید نصب کنید، فایل `database.sql` بکاپ را از طریق phpMyAdmin ایمپورت کنید و ربات را آپدیت/ری‌استارت کنید. راهنمای کامل قدم‌به‌قدم (و حالت ربات‌های نسخهٔ 2.1.4 و قدیمی‌تر): [بکاپ و ریستور](/docs/admin/backup-restore).

</Accordion>
</Accordions>

## فروش و خرید [#sales]

<Accordions>
<Accordion title="کاربر دکمهٔ خرید سرویس را نمی‌بیند یا پیام «فروش بسته است» می‌گیرد">

این موارد را به ترتیب چک کنید:

1. **⚙️ تنظیمات ربات → وضعیت فروش** روشن باشد. **پیش‌فرض خاموش است.** در حالت خاموش، کاربر پیام «⛔️ فروش توسط ادمین بسته است.» می‌گیرد.
2. حداقل یک پنل **فعال** باشد و **🛒 خرید سرویس** آن ✅ باشد (**📚 منوی پنل ها → 📉 وضعیت پنل ها → پنل**). اگر هیچ پنلی فروش نداشته باشد، دکمه‌های **🛍 خرید سرویس** و **🔑 سرویس های من** از منو حذف می‌شوند.
3. برای پنل حداقل یک **پلن** ساخته باشید (**🗞 ساخت پلن**).
4. اگر برای پنل **🧢 سقف خرید سرویس** گذاشته‌اید و پر شده، آن پنل در لیست خرید نمی‌آید.
5. اگر «فقط مینی‌اپ» روشن است، منوی معمولی نمایش داده نمی‌شود و همه‌چیز در وب‌اپ است.

[چک‌لیست راه‌اندازی](/docs/getting-started/first-setup)

</Accordion>
<Accordion title="دکمهٔ «🎁 دریافت تست» نمایش داده نمی‌شود">

دکمه فقط وقتی دیده می‌شود که **هر سه** شرط برقرار باشد:

1. **⚙️ تنظیمات ربات → 🛍 خرید، تمدید و سرویس تست → دکمه دریافت تست** روشن باشد (پیش‌فرض خاموش).
2. حداقل یک پنل فعال، تست ارائه دهد: **(پنل) → 🧪 تنظیمات تست → 🆓 ارائهٔ تست از این پنل**.
3. کاربر **قبلاً تست نگرفته باشد**. برای اجازهٔ دوباره از **🔄 ریست دریافت تست** استفاده کنید.

[سرویس تست](/docs/user/trial)

</Accordion>
<Accordion title="ربات برای کاربران پیام «ربات به‌صورت موقت در دسترس نیست» می‌دهد">

**⚙️ تنظیمات ربات → وضعیت ربات** خاموش است. در این حالت فقط ادمین‌ها می‌توانند از ربات استفاده کنند. آن را روشن کنید. (دکمهٔ «📢 وضعیت بروزرسانی» این پیام به یوزرنیم `ADMIN_ID_TAG` در `.env` لینک می‌شود.)

</Accordion>
<Accordion title="در افزایش موجودی فقط «❌ شارژ حساب غیرفعال می‌باشد» نمایش داده می‌شود">

هیچ روش پرداختی روشن نیست. در **⚙️ تنظیمات ربات → 💳 پرداخت‌ها و روش‌های شارژ** حداقل یکی از «دکمه کارت دستی»، «دکمه درگاه ارزی»، «دکمه پرداخت استارز» یا «درگاه TonPays» را روشن کنید و تنظیمات همان روش را در **💳 تنظیمات درگاه** کامل کنید. [تنظیمات درگاه](/docs/admin/gateway)

</Accordion>
</Accordions>

## پرداخت، لاگ و بکاپ [#logs]

<Accordions>
<Accordion title="رسیدهای کارت به کارت به دستم نمی‌رسد / کاربر پیام «❌ رسید شما ثبت نشد» می‌گیرد">

رسیدها به مقصد لاگ **💳 کارت به کارت دستی** فرستاده می‌شوند. اگر نه این مقصد و نه `LOG_CHANNEL` تنظیم شده باشد، رسید **ثبت نمی‌شود**.

1. **پنل مدیریت → 📝 مدیریت لاگ‌ها → 💳 کارت به کارت دستی** را روی یک کانال یا سوپرگروه ست کنید.
2. ربات باید در آن کانال/گروه **ادمین** باشد (اجازهٔ ارسال پیام).
3. آیدی عددی درست باشد (معمولاً با `-100` شروع می‌شود). بعد از ست کردن باید پیام تست در کانال بیاید.
4. **📊 وضعیت لاگ‌ها** را بزنید و مقصد را ببینید.

[مدیریت لاگ‌ها](/docs/admin/logs)

</Accordion>
<Accordion title="بکاپ ارسال نمی‌شود">

بکاپ **فقط** به مقصد **🗄 بکاپ ربات** در **📝 مدیریت لاگ‌ها** فرستاده می‌شود (نه به `LOG_CHANNEL`). اگر تنظیم نشده باشد، پیام «❌ کانال لاگ بکاپ تنظیم نشده است.» می‌آید.

- مقصد بکاپ را ست کنید و ربات را ادمین کانال کنید.
- در **📦 بکاپ ربات** دکمهٔ **🚀 بکاپ همین الان** را برای تست بزنید.
- فاصلهٔ خودکار پیش‌فرض ۲۴ ساعت است؛ اگر روی «⏸ خودکار خاموش» است، با **⚙️ تنظیم فاصله** عدد بزرگ‌تر از صفر بدهید.

[بکاپ و ریستور](/docs/admin/backup-restore)

</Accordion>
</Accordions>

## وب‌هوک و اطلاع‌رسانی [#webhook]

<Accordions>
<Accordion title="وب‌هوک پنل پاسارگارد خطای 403 می‌گیرد">

ربات درخواست وب‌هوک را بدون هدر درست رد می‌کند:

| پیام | علت |
|------|-----|
| `Signature header missing` | هدر `x-webhook-secret` در تنظیمات وب‌هوک پنل اضافه نشده |
| `Invalid shared secret` | مقدار Secret اشتباه است |

Secret درست در دیتابیس است: phpMyAdmin ← دیتابیس `pasarguardbot` ← جدول `secrets` ← ردیف `webhook_secret` ← ستون `value`. گزینهٔ **`9) Show webhook & URLs`** آدرس و محل آن را نشان می‌دهد. مقدار `WEBHOOK_SECRET` در `.env` (اگر از نسخه‌های قدیمی مانده) **استفاده نمی‌شود**.

</Accordion>
<Accordion title="پیام‌های هشدار حجم و زمان به کاربران نمی‌رسد">

هر پنل دو حالت اطلاع‌رسانی دارد (دکمهٔ **📡 اطلاع‌رسانی** در تنظیمات پنل):

- **🤖 حالت ربات** (پیش‌فرض): ربات خودش حدود هر دقیقه پنل را چک می‌کند. نیازی به وب‌هوک ندارد.
- **🔔 حالت وب‌هوک**: پنل پاسارگارد رویدادها را به ربات می‌فرستد. باید وب‌هوک در پنل (**Settings → Webhook**) درست ست شده باشد.

اگر روی 🔔 هستید ولی پیامی نمی‌آید:

1. در پنل، وب‌هوک روشن و ذخیره شده باشد و آدرس `http(s)://…:6160/api/webhook` باشد.
2. هدر `x-webhook-secret` درست باشد (سؤال قبلی).
3. سرور پنل به پورت `6160` سرور ربات دسترسی داشته باشد (فایروال).
4. اگر SSL روی ربات فعال است، آدرس باید `https://` و با دامنه باشد.

[اطلاع‌رسانی حجم و زمان](/docs/admin/panels/notifications)

</Accordion>
</Accordions>

## پنل پاسارگارد [#panel]

<Accordions>
<Accordion title="ورود به پنل ناموفق است (هنگام افزودن پنل خطا می‌دهد)">

- **آدرس بدون مسیر:** فقط `https://panel.example.com` یا `https://panel.example.com:8000`. چیزی مثل `/dashboard` یا `/admin` اضافه نکنید.
- **پروتکل و پورت درست:** همان آدرسی که در مرورگر پنل را باز می‌کند (http یا https و پورت پنل).
- **نوع ورود:** اگر **👤 نام کاربری و رمز** را انتخاب کرده‌اید، یوزر و رمز **ادمین پنل** را بدهید؛ اگر **🔑 API Key**، کلید API ساخته‌شده در پنل را. این دو را با هم اشتباه نکنید.

پیام‌های خطا:

| پیام | معنی |
|------|------|
| `Error: Unauthorized. Check username/password or API Key.` | یوزر/رمز یا API Key اشتباه است |
| `Error: Forbidden (403). Check admin permissions.` | ادمین دسترسی کافی ندارد (از ادمین اصلی/sudo استفاده کنید) |
| `Error: Panel URL or API path not found (404).` | آدرس اشتباه است یا مسیر اضافه دارد |
| `Error: Panel connection timed out…` / `Could not connect to panel…` | سرور ربات به پنل دسترسی ندارد (فایروال، دامنه، پورت) |

از سرور ربات تست کنید: `curl -I https://panel.example.com:8000`

</Accordion>
</Accordions>

## وب‌اپ و Mini App [#webapp]

<Accordions>
<Accordion title="دکمهٔ «🚀 ورود به اپلیکیشن» یا «🖥 پنل تحت وب» نمایش داده نمی‌شود">

1. `WEBAPP_URL` در `.env` باید با **`https://`** شروع شود. با `http://` یا خالی، هیچ دکمهٔ وب‌اپی نمایش داده نمی‌شود.
2. بعد از تغییر `.env` ربات را ری‌استارت کرده باشید.
3. برای دکمهٔ کاربران: **⚙️ تنظیمات ربات → 🚀 مینی‌اپ** باید روی «دکمه در منو» باشد (پیش‌فرض «خاموش»). در حالت «فقط مینی‌اپ» منوی ربات کامل با یک دکمهٔ وب‌اپ جایگزین می‌شود.
4. اگر دکمهٔ منوی اصلی را از **⌨️ مدیریت دکمه‌های کیبورد** مخفی کرده‌اید، دوباره نمایشش دهید.

[دامنه و SSL](/docs/getting-started/ssl) · [وب‌اپ](/docs/webapp)

</Accordion>
<Accordion title="تلگرام آدرس وب‌اپ را قبول نمی‌کند («تلگرام این آدرس را نپذیرفت»)">

تلگرام فقط این را قبول می‌کند:

- `https://` (نه `http://`)
- **دامنه** (نه آی‌پی خام مثل `https://1.2.3.4:6160`)
- گواهی **معتبر** (نه self-signed؛ Let's Encrypt مناسب است)

با `pasarguardbot ssl` گواهی بگیرید و `WEBAPP_URL=https://دامنه:6160/api/webapp` بگذارید. در مرورگر `https://دامنه:6160/webapp` را باز کنید؛ اگر مرورگر خطای گواهی داد، تلگرام هم قبول نمی‌کند. [دامنه و SSL](/docs/getting-started/ssl)

</Accordion>
</Accordions>
