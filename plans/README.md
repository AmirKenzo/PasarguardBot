## Decisions and boundaries

1. **Billing:** Add an observation-time expected-baseline contract to the existing transaction. Preserve legitimate reset behavior rather than hiding it with a high-watermark-only formula.
2. **SMS:** Move invoice completion, wallet credit, and transaction recording into one existing-database transaction. Redis markers and Telegram delivery are not the financial commit boundary. No payment framework or notification outbox is proposed.
3. **Recovery:** Reuse the existing three reseller statuses and disable markers. Positive funds restore admin/system-disabled users; nonpositive funds remain frozen. Manually reseller-disabled users stay disabled.
4. **Coordination:** Add only a bot-reseller-specific, token-owned, renewable Redis lease using the installed client/key builder. Leave generic bot locks unchanged. Reads remain available, but affected mutations refuse/defer when Redis cannot coordinate them. A fixed expiring lock with unconditional release is not an acceptable substitute.

No schema changes, dependency additions, UI changes, or legacy panel-reseller refactors are planned. No production records or historical wallet amounts may be repaired automatically by these plans.

## Verification baseline and audit limitations

Repository verification commands discovered during recon:

- Dependency installation: `uv sync --frozen` (execution worktree only).
- Backend tests: `uv run --no-sync pytest -q`.
- Python lint: `uv run --no-sync ruff check --no-cache <scoped paths>`.

The scoped Ruff check passed during the audit. Four isolated source-extraction checks reproduced the stale charge, pre-credit invoice claim, frozen/suspended recovery failure, and create/revoke interleaving. These are evidence of the defects, not substitutes for committed production-module regression tests.

Full pytest was not run in the advisor checkout because `tests/conftest.py:36-46` writes/removes a minimal `.env` if absent. In a disposable execution worktree that behavior is expected; never bring in a production `.env` or Telethon session. New test commands in the plans are future verification gates, not claimed passing results. SQLite regression tests cannot establish production MySQL lock semantics.

The audit was a quick hotspot review of recent bot-reseller billing/lifecycle, SMS payment processing, and their tests. It did not assess the whole repository, broader performance/architecture, dependency vulnerabilities, live panel behavior, browser flows, or production load. External panel writes and local commits are still not an atomic distributed transaction: ambiguous remote completion, process crashes, or failed compensation need explicit reconciliation.

## Findings considered and rejected

- **A lower counter is always a bug:** rejected. Reset-from-zero behavior is deliberate and has an existing regression test; stale observations must be rejected without removing legitimate reset accounting.
- **Per-minute debt is itself a defect:** rejected. Admin documentation explicitly allows debt up to a billing interval because usage is observed after it happens; these plans do not introduce prepaid reservation.
- **The reseller endpoints have no ownership checks:** rejected as a blanket claim. `_owned_user` verifies the reseller and live row, and create/edit check grants; the confirmed gap is concurrency across mutation paths.
- **The repository has no verification baseline:** rejected. CI has backend tests/lint and a typechecked frontend build. The advisor's choice not to trigger `.env` writes is not evidence that those commands are broken.
- **Final usage after direct external deletion must always be recoverable:** rejected. The admin guide explicitly documents that traffic between the last snapshot and a direct panel deletion cannot be recovered from a missing user.
